# GymFix — End-to-End Product Management Case Study

### From Problem Discovery to Functional MVP

**Role:** Product Manager — Independent Portfolio Project  
**Product:** Gym Equipment Maintenance Management Platform  
**Tools:** Lovable, GitHub, Excel, Markdown  
**Status:** Prototype Completed  
**Live Demo:** https://gymfix-demo.lovable.app/

---

## 1. Executive Summary

GymFix is an interactive web application concept designed to improve gym equipment fault reporting, maintenance coordination, and repair visibility.

This independent project explores the end-to-end Product Management process, including problem discovery, secondary research, product strategy, prioritisation, requirements definition, prototyping, and evaluation planning.

The outcome is a functional browser-based prototype with seven manually verified functional checks.

## 2. The Problem

Gym equipment faults can disrupt workouts and create operational challenges.

Preliminary secondary research identified public accounts involving:
- Prolonged equipment downtime.
- Uncertainty about repair progress.
- Maintenance coordination constraints.
- Existing informal or low-cost reporting alternatives.

These findings motivated an investigation into whether a lightweight maintenance platform could improve the reporting-to-resolution experience.

## 3. Research & User Understanding

The project used publicly available discussions and competitor research.

Three provisional user groups were identified:

1. Gym members.
2. Gym managers and branch staff.
3. Maintenance technicians.

Evidence-informed personas, candidate Jobs-to-Be-Done, and illustrative user journeys were developed.

No direct user interviews were conducted.

## 4. Product Strategy

**Vision:** Make gym equipment maintenance transparent, accountable, and easy to manage.

**Proposed target customer:** Smaller gym operators.

**Value proposition:** A lightweight platform connecting equipment fault reporting, maintenance ownership, and repair progress visibility.

The target segment and commercial differentiation remain unvalidated.

## 5. Feature Prioritisation

A RICE framework was used to evaluate candidate features using hypothetical reach, impact, confidence, and effort estimates.

The resulting MVP focused on:
- Equipment fault reporting.
- Maintenance ticket management.
- Technician assignment.
- Repair status tracking.
- Repair coordination.

Advanced analytics, predictive maintenance, and automated notifications were deferred.

## 6. Product Requirements

A Product Requirements Document defined the proposed workflows, functional requirements, user stories, and acceptance criteria.

The central workflow was:

Member Report → Ticket Creation → Staff Assignment → Technician Repair → Resolution

The requirements informed the Lovable prototype.

## 7. Prototype Development

GymFix was developed using Lovable as an interactive browser-based demonstration.

The prototype includes role-specific Member, Staff, and Technician interfaces.

An initial navigation issue was addressed before functional validation.

**Live prototype:** https://gymfix-demo.lovable.app/

## 8. Functional Validation

Seven manual functional checks were completed.

| Test | Result |
|---|---|
| Submit fault report | Pass |
| Generate ticket reference | Pass |
| View ticket in staff dashboard | Pass |
| Assign technician | Pass |
| Open technician interface | Pass |
| Update and view ticket status | Pass |
| Retain ticket after browser refresh | Pass |

The checks collectively covered seven tested behaviours, including submission, visibility, assignment, navigation, status updates, and persistence.

**Result: 7/7 checks passed.**

These results apply to the tested browser-based demo environment.

## 9. Usability Evaluation

A simulated usability exercise was conducted to demonstrate task-based evaluation, KPI interpretation, and iteration planning.

The simulation used hypothetical participants and outcomes.

No real participant usability testing was conducted, and no actual usability improvement has been established.

## 10. Product Roadmap

**Now:** Validate the MVP with real users and operators.

**Next:** Explore shared persistence, authentication, and maintenance history.

**Later:** Consider notifications, multi-branch support, analytics, and preventive maintenance.

Roadmap priorities depend on further validation.

## 11. Key Learnings

- Investigate problems before defining solutions.
- Prioritise core workflows over feature breadth.
- Use scoring frameworks alongside qualitative judgement.
- Verify functional behaviour before claiming an MVP works.
- Distinguish simulated findings from observed results.
- Treat customer adoption and product-market fit as open questions.

## 12. Limitations

- No real gym deployment.
- No validated commercial demand.
- No direct user interviews.
- No observed participant usability results.
- No shared production database or real authentication.
- No measured reduction in equipment downtime.

## 13. Conclusion

GymFix demonstrates an end-to-end Product Management planning and prototyping process.

The project resulted in a functional interactive demonstration, documented product decisions, and a proposed roadmap for further validation.

Its primary outcome is a documented PM case study and working prototype, not proven business impact.
